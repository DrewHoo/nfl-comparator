# Project notes for the agent

- What it is: a query engine for NFL career-point comparisons ("Mahomes has 115 wins through his first 150 starts"). A reader sets a five-slot sentence (who · did what · how much · over which games · against whom) and the board ranks every career, or every player-season, by its value at that window. The planning spec and the research are in the CFB repo: `cfb-streak-king/specs/nfl-career-point.spec.md`, `specs/research/nfl-career-point-factoids.md` (23 factoids taken apart) and `specs/research/nfl-data-sources.md` (why the ledger starts in 1999).
- Data: nflverse release files, CC BY 4.0. `npm run fetch` downloads `stats_player_week_<season>.csv.gz` (1999 on), `games.csv` and `players.csv.gz` into `data/raw/` (gitignored; the running season's files refetch after a day). `npm run ledger` (`scripts/build-ledger.mjs`) joins the stat rows to the schedule and writes one file per position group to `src/data/<POS>.json` (committed; the site builds without the raw files). A row is a game the player recorded a stat in, with the result, the start flag (QBs only, from the schedule's `home_qb_id`/`away_qb_id`), the team's game number that season (`tgn`) and the stat line; `COLS` in the builder is the layout and `src/lib/ledger.ts` decodes it. The schedule's team codes are normalized to the current franchise codes (STL→LA, SD→LAC, OAK→LV) because the stat rows use those.
- Rulings the words rest on (also in `Notes.jsx`): a start is nflverse's starting QB, the one who played most of the game, which differs from Pro Football Reference on a handful of early exits (Brady 2005 wk 17, 2014 wk 17, 2022 wk 18), so a start count can sit one or two off PFR's; a game is a stat-line game, so linemen and defenders aren't in the ledger yet; a career that began before 1999 (`debut` from `players.csv` rookie season) sits out career fields, since its first N is unknowable, but its seasons count in player-season fields; the regular season is the default and `scope=all` adds the playoffs; "team games of a season" count the team's schedule, so a missed game is a gap the window still counts; ranks are competition ranks with ties.
- The known-answer gate is `src/lib/query.test.ts`: Mahomes 115 wins through 150 starts (playoffs included, the scope both viral posts used), 100 through 131 regular-season starts, 116-35 through 151 games; Bryce Young one of four since 2011 with 280+ yards and a TD in each of the team's first five; Allen's TDs through 120 games with Mahomes at 280; Nacua fastest to 250 receptions. `scripts/gate.mjs` prints the same numbers. Add a gate for every factoid the site is asked to reproduce, with the publisher's definition noted where it differs.
- Code layout: `src/lib` is TypeScript (`npm run typecheck`), components JSX. `query.ts` is the engine (`evaluate` → ranked rows and the ones still inside the window; `curve`, `crossings`, `toMatch` are the peer readings), `stats.ts` the stat catalog (noun, thresholds, positions), `words.ts` every sentence the page says, `url.ts` the query in the URL (one param a slot, defaults omitted, `t` the open player). The QB ledger ships with the page; the other positions load on demand (`import.meta.glob` in `App.jsx`).
- Look: College Football Streak King's (dark stadium palette, Graduate for numbers, Source Serif for words, Plex Mono labels, dashed-underline pickers; `Picker.jsx` and `Icons.jsx` are copied from it). Every select is `Picker.jsx`, a Radix dropdown; no native `<select>`. Rust is for data, never chrome.
- Vite + React static site for GitHub Pages under drewhoover.com, from the dataviz-project-template: `package.json` "name" is the URL slug and must equal the repo name; `site.config.js` the title and OG copy; `npm run build` is `vite build` plus `scripts/prerender.mjs`, so `main.jsx` hydrates and nothing reads `window` during render (URL state is applied in an effect). Shareable state goes in the URL with `replaceState`. Analytics is `window.dhAnalytics?.track`, optional-chained. Not on GitHub yet; `.github/workflows/deploy.yml` is the template's and deploys on push to `main` once the repo exists and Pages is enabled.
- Dev server: `npm run dev` (the preview config runs it on 5175). Tests: `npm test` (Vitest, next to the code).
- Next, from the spec: team and coach ledgers (the schedule has coaches 1999 on), age windows, the weekly digests (crossings this week, within reach next week), share cards, the definition landing pages, and the historical comparators as a receipts research project.

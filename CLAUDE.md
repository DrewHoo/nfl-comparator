# Project notes for the agent

- AGENTS.md lists the idiosyncrasies of the data and the logic the first build turned up (team codes, stat-line games, the start flag, pre-1999 careers, what each sequence means). Read it before changing the ledger builder or the engine, and add to it when a gate or a reader teaches us a new one.

- What it is: a query engine for NFL career-point comparisons ("Mahomes has 115 wins through his first 150 starts"). A reader sets a five-slot sentence (who · did what · how much · over which games · against whom) and the board ranks every career, or every player-season, by its value at that window. The planning spec and the research are in the CFB repo: `cfb-streak-king/specs/nfl-career-point.spec.md`, `specs/research/nfl-career-point-factoids.md` (23 factoids taken apart) and `specs/research/nfl-data-sources.md` (why the ledger starts in 1999).
- Data: nflverse release files, CC BY 4.0. `npm run fetch` downloads `stats_player_week_<season>.csv.gz` (1999 on), `games.csv` and `players.csv.gz` into `data/raw/` (gitignored; the running season's files refetch after a day). `npm run ledger` (`scripts/build-ledger.mjs`) joins the stat rows to the schedule and writes one file per position group to `src/data/<POS>.json` (committed; the site builds without the raw files). A row is a game the player recorded a stat in, with the result, the start flag (QBs only, from the schedule's `home_qb_id`/`away_qb_id`), the team's game number that season (`tgn`) and the stat line; `COLS` in the builder is the layout and `src/lib/ledger.ts` decodes it. The schedule's team codes are normalized to the current franchise codes (STL→LA, SD→LAC, OAK→LV) because the stat rows use those, and the 2001–2002 stat rows that give a Jaguar's home games to the visitor are swapped back (`SWAPPED` in the builder; AGENTS.md).
- Rulings the words rest on (also in `Notes.jsx`): a start is nflverse's starting QB, the one who played most of the game, which differs from Pro Football Reference on a handful of early exits (Brady 2005 wk 17, 2014 wk 17, 2022 wk 18), so a start count can sit one or two off PFR's; a game is a stat-line game, so linemen and defenders aren't in the ledger yet; a career that began before 1999 (`debut` from `players.csv` rookie season) sits out career fields, since its first N is unknowable, but its seasons count in player-season fields; the regular season is the default and `scope=all` adds the playoffs; "team games of a season" count the team's schedule, so a missed game is a gap the window still counts; ranks are competition ranks with ties.
- The known-answer gate is `src/lib/query.test.ts`: Mahomes 115 wins through 150 starts (playoffs included, the scope both viral posts used), 100 through 131 regular-season starts, 116-35 through 151 games; Bryce Young one of four since 2011 with 280+ yards and a TD in each of the team's first five; Allen's TDs through 120 games with Mahomes at 280; Nacua fastest to 250 receptions. `scripts/gate.mjs` prints the same numbers. Add a gate for every factoid the site is asked to reproduce, with the publisher's definition noted where it differs.
- Code layout: `src/lib` is TypeScript (`npm run typecheck` runs the root tsconfig and the worker's, `workers/share/tsconfig.json`, which swaps the DOM for the workers runtime), components JSX. `query.ts` is the engine (`evaluate` → ranked rows and the ones still inside the window; `curve`, `crossings`, `toMatch` are the peer readings), `stats.ts` the stat catalog (noun, thresholds, positions), `words.ts` every sentence the page says, `share.ts` the words a shared address carries (a board's and a comparison's title and description, the share button's text, a player page's lead; the worker, the tab title, the share sheet and the prerender all read it; WNBA Comparator has the same module), `compare.ts` the panel's reading (`compare`, `peerOf`, the crossing and to-match words), `url.ts` the query in the URL (one param a slot, defaults omitted, `t` the open player; `toHref` writes a named board's path instead, `parseUrl` reads a landing page's params over its query), `landing.ts` the named boards (`specs/seo.spec.md`: a slug and a full query each, `landingOf` finds a query's page, `h1Words` in `words.ts` is their wording and every board's h1). The first season is never typed: components read the ledger's `firstSeason` (or `board.since`), scripts `FIRST_SEASON` from `scripts/lib/window.mjs`, which `site.config.js` imports for the description. The QB ledger ships with the page; the other positions load on demand (`import.meta.glob` in `App.jsx`).
- Look: College Football Streak King's (dark stadium palette, Graduate for numbers, Source Serif for words, Plex Mono labels, dashed-underline pickers; `Picker.jsx` and `Icons.jsx` are copied from it). Every select is `Picker.jsx`, a Radix dropdown; no native `<select>`. Rust is for data, never chrome.
- Page anatomy, Streak King's: dateline with the icon bar (finder, Ko-fi cup, share), h1, the sentence, the board with the panel inline, then `Notes.jsx`: What to read next (one line per sibling site; keep them current with each site's own description), "Using a comparison from here" (the citing ask and the Ko-fi/Wayback line), Method (`id="method"`, the player pages link to it, the rulings above), the sibling line; then the footer in `App.jsx`. Ko-fi is `KOFI_URL` in `Notes.jsx`, three placements, no button or badge. Share is `src/hooks/useShare.ts`: `navigator.share({ title, text, url })` where there is one, else "text url" on the clipboard and a "copied" flash; the text is the open row's claim or the sentence (`shareText`), a player page's lead line (`playerLead`). `document.title` follows the query and the open row (an effect in `App.jsx`, the worker's own words), so the tab never lags a picker.
- Vite + React static site for GitHub Pages under drewhoover.com, from the dataviz-project-template: `package.json` "name" is the URL slug and must equal the repo name; `site.config.js` the title and OG copy; `npm run build` is `vite build` plus `scripts/prerender.mjs`, so `main.jsx` hydrates and nothing reads `window` during render (URL state is applied in an effect). Shareable state goes in the URL with `replaceState`. Analytics is `track` in `src/lib/analytics.ts` (`window.dhAnalytics?.track`, optional-chained): `query { words }`, `open { player }`, `peer { player, vs }`, `share { words, player }` on the board, `share player { player }` on a page, `player page { player }`, `record { player, words }`, `kofi { from }` with `icons board`, `icons player`, `notes` or `footer`; the worker's `share unfurl` and `share card` are below. The repo is `DrewHoo/nfl-comparator`; `.github/workflows/deploy.yml` deploys on push to `main`.
- Dev server: `npm run dev` (the preview config runs it on 5175). Tests: `npm test` (Vitest, next to the code).
- Images: `npm run gen:favicon` copies drewhoover.com's own favicon set from the index repo (every sibling site wears it); `npm run gen:og` draws `public/og.png` and `public/card.png` from the real default board, text as opentype.js outlines with the fonts under `scripts/fonts/` and the heading in Georgia Bold from the Mac's own copy (AGENTS.md). Both draw the page's default board (regular season) and are committed; re-run `gen:og` after a redesign or when a fresher board is worth committing, and open the PNGs. The player pages' cards are not committed: the prerender draws `dist/player/<id>/og.png` for each at build (`scripts/lib/og-player.mjs`; the drawing kit both share is `scripts/lib/og.mjs`), and each page's `og:image` points at its own. Every card keeps its glyphs inside the centered 720px column (x 240–960): Reddit's compact feed center-crops the 1.91:1 card to a near-square, and Streak King learned that the hard way. The project card on the index site is `src/content/projects/nfl-comparator.md` there, with `card.png` as its cover; update it in the same pass as a redesign.
- The share worker (`workers/share/`, a Cloudflare worker on `drewhoover.com/nfl-comparator/*` in front of GitHub Pages, Streak King's pattern) makes a shared board or comparison unfurl as itself: a URL with a query gets a title and description from `src/lib/share.ts` (`boardText`, `compareText`) and `og:image` pointing at `share/og.png?<the same params>`, which the worker draws on demand with workers-og from the ledger the prerender publishes at `dist/data/<POS>.json`, running the site's own `evaluate`. The card is a board's top rows, or a comparison's two sides with the panel's chart (`card.ts`). `vs=<key>` in the URL is the panel's peer (`url.ts`; it rides only with `t`), so a shared comparison opens as it was shared; the card draws the panel's reading from `compare.ts` so it says what the panel shows. Bump `CARD_VERSION` when a card changes. It reports crawlers to Mixpanel server-side, the index site's project with the embed's public token (`share unfurl` when a crawler fetches a reworded URL, `share card` for every card, with the query's slots; never a browser's user agent or an IP), since the bot that fetches a shared link runs no script; a local origin reports nothing. The worker deploys from `deploy.yml` on a push (not the scheduled refresh) and needs a `CLOUDFLARE_API_TOKEN` repo secret. Local: `npx vite preview` as the origin and `npx wrangler dev -c workers/share/wrangler.jsonc --var ORIGIN:http://localhost:4173` (both in `.claude/launch.json`). Anything that fails passes through; the player pages pass through untouched.
- `deploy.yml` builds on push from the committed ledgers, and on the Tuesday 12:00 UTC schedule (or a manual run) refetches nflverse and rebuilds the ledger first, so the week's games reach the site without a commit. After the deploy, `scripts/indexnow.mjs` pings Bing with the board and the named boards (the whole sitemap on the scheduled run); the key is the 32-hex `.txt` under `public/`.
- Search (`specs/seo.spec.md`): the prerender writes the root (title from `rootTitle` in `share.ts`, an ItemList of the default board's top ten), a page per named board at `dist/<slug>/` with its own card (`scripts/lib/og-board.mjs`, the same drawing `gen-og` commits for the root), a page per player (title "Name: every record he holds…", an ItemList of his faces), `llms.txt` and the sitemap. Unnamed query URLs canonicalize to the root; the worker points a root URL whose query is a named board's at that page.
- Player pages (`specs/player-pages.spec.md`): `src/lib/records.ts` mines what every player leads (held and set-and-broken rows, each an interval of N, scored in bits with the knobs in `RECORDS`, folded to one row per claim). `scripts/build-records.mjs` writes `public/players/<id>.json` (gitignored; `npm run records`, and `npm run build` runs it first), `PlayerPage.jsx` renders `/player/<id>/` from the file (the prerender writes one HTML per player with the file embedded), `?tune=1` opens the tuner, and `records.test.ts` is the golden gate. `node scripts/records.mjs QB "Cam Newton"` prints a page with its terms.
